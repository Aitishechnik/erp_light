## 0. Что это за проект и что в него НЕ входит

`erp_lite` — **намеренно лёгкое** приложение для пяти ролей: **Менеджер по продажам**,
**Коммерческий директор**, **Директор по закупкам**, **Менеджер по закупкам (импорт)**,
**Исполнительный директор** (аналог ген. директора). Политика изменилась: универсального
ERP больше не строим.

**Зона 1С (не дублировать здесь):** производство, склады, внешние интеграции,
бухгалтерия, счета и проводки, курсовые разницы. Данные приходят выгрузками
(`.xlsx`) либо вводятся вручную.

**Зона `erp_lite`:** партии и остатки с оперативной себестоимостью, планирование
продаж → закупок, матрица ценообразования, PnL / Cashflow, таск-трекер, RBAC
(вход и пять ролей уже есть).

Меню разделов сгруппировано по категориям (раскрываются по стрелке, открыта одна):
**Планирование** (продажи, матрица цен) · **Закупки** (поступления, план закупок,
поставщики) · **Справочники** (номенклатура, контрагенты, валюты, страны) · **Отчёты**
(остатки, PnL / Cashflow) · **Задачи** · **Администрирование** (загрузка данных,
пользователи, настройки).

Предыдущий проект (`/mnt/extraspace/erp_v_2`, форк `custom_erp`) — **справочник**.
Он не запускается и не изменяется; из него перенесена только оперативная формула
себестоимости. Бухгалтерский слой себестоимости сознательно **не** переносился.

## 2. Команды

```sh
docker compose up -d --wait          # PostgreSQL проекта (проверяет healthcheck)

cd backend
make install                         # venv на python3.12 + зависимости (один раз)
make db-bootstrap                    # схема (create_all) — пока миграций нет
make run                             # API на 127.0.0.1:4111
make check                           # ВОРОТА: ruff format --check + ruff check + mypy + pytest
make test                            # только pytest

cd frontend
pnpm install                         # один раз
pnpm dev                             # UI на 127.0.0.1:4110 (проксирует /api → 4111)
pnpm typecheck && pnpm lint && pnpm test && pnpm e2e && pnpm build
```

## 3. База данных

- Своего контейнера и тома хватает: **не подключаться** к БД других проектов.
- `pytest` в `conftest.py` делает `drop_all/create_all` по `TEST_DATABASE_URL`
  (`erp_lite_test`). Никогда не подставлять сюда рабочую или чужую базу.
- Alembic подключён как зависимость, но история миграций **пока пустая**: схема
  создаётся `Base.metadata.create_all` (`make db-bootstrap`). Первую миграцию
  заводим в тот момент, когда схема перестанет быть одноразовой, и с этого
  момента `create_all` для основной базы не используем.

## 4. Правила кода и данных

1. **Деньги — только `Numeric`/`Decimal`.** `Float` в финансовых полях запрещён;
   pre-commit-хук это блокирует. В JSON деньги уходят **строкой** (точность не теряется).
2. Оперативная формула себестоимости живёт в одном месте —
   [`backend/app/services/cost.py`](backend/app/services/cost.py). Менять её —
   только с обоснованием и тестами на векторах из `erp_v_2`.
3. Изменения денежной логики, схемы данных и форматов выгрузок 1С — **SLOW TRACK**:
   сначала согласование контракта данных, потом код.
4. Секреты — только в `.env` (в git не попадает); ключи не логировать.
5. Сами файлы выгрузок 1С в git не кладём — каталог `data/` в `.gitignore`.

## 5. Чек-лист «готово»

1. `cd backend && make check` → зелёный.
2. `cd frontend && pnpm typecheck && pnpm lint && pnpm test && pnpm build` → зелёные.
3. Для изменений интерфейса — `pnpm e2e` и реальная проверка UI (skill `web-ui-verify`).
4. В отчёте перечислено, что **не** проверено.
5. Коммит — conventional (`feat|fix|refactor|test|chore|docs`), мелкий и осмысленный.
