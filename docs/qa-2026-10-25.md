# QA-сценарий: планирование, закупки, доступы и гонки

Дата: 2026-10-25. Стенд: `erp_lite` (2026 — рабочие данные, 2027 — демо-моки,
2028–2030 — временные данные проверки, после прогона удалены).

## 1. Что проверялось

1. **Механика планирования и закупок:** план продаж → годовой план → план закупок →
   поступления; факт и перезакуп; пересмотр плана продаж; блокировки строк.
2. **Гонки состояний:** одновременные загрузки, сохранения, отправка/утверждение,
   привязка к строке плана и её удаление.
3. **Доступы:** пять ролей × действия (API и браузер).
4. **Читаемость интерфейса:** 1280 / 1440 / 1920 px, плотность экранов.
5. **20+ строк плана** и **тёмная тема**.
6. **Нагрузка и ожидание блокировок.**

## 2. Механика — пройдено

Автотесты: `cd backend && make check` — **162 passed**; frontend typecheck, lint,
**85 unit**, **16 e2e**, build — зелёные.

Живые проверки (2028):

| Проверка | Результат |
|---|---|
| Пустой план закупок нельзя отправить | 400 «Нельзя отправить пустой план» |
| План без цены нельзя отправить | 400 «Укажите цену у всех строк» |
| Корректировка плана продаж меняет годовой план | годовой план → `revision`, повторно согласован |
| План закупок видит пересмотр источника | `source.state = changed` |
| Отправка без подтверждения пересмотра | 409 «План продаж изменился — примите изменения» |
| «Принять к сведению» → отправка → утверждение ГД | 200 → 200 → 200 |
| Перезакуп больше плана | `факт 120 · 120 %`, сохранение не блокируется |
| Связанную строку плана нельзя удалить/сменить сырьё | 409 (тесты и живой прогон) |
| План с поступлениями нельзя удалить | 409 (тесты) |
| Факт по месяцам, границы года, ссылка после растаможки | тесты `test_receipt_plan_link.py` |

Дополнительно:

- **Отправка годового плана против утверждения последнего плана менеджера** (2030):
  отправка получила 409, утверждение — 200; годовой остался черновиком, повторная
  отправка — 200, утверждение ГД — 200. Частичного годового плана не возникло,
  `is_stale = false`.
- **Привязка к удаляемой строке** (2029): 10 из 10 гонок без молчаливой потери —
  либо привязка 400 и строка удалена, либо (последовательно) удаление 409 «с ней
  связано поступлений: 1».
- **24 строки** (2029): API отдаёт план за ~30 мс, 43 КБ; на экране 24 строки.

## 3. Гонки — найдены и исправлены

| Сценарий | Было | Стало |
|---|---|---|
| Две одновременные загрузки одного номера поступления | 500 (IntegrityError) | 200 + 409, одно поступление |
| Две одновременные правки строк плана | 10/10 — смесь двух версий | 0/10 смеси |
| Двойная отправка плана | оба 200 | 200 + 409 |
| Двойное утверждение плана | оба 200 | 200 + 409 |
| Утверждение и правка одновременно | правка могла пройти после утверждения | правка 409 |
| Две одновременные правки поступления | тот же шаблон замены строк | 0/10 смеси |
| Привязка к строке, которую одновременно удаляют | по коду — молчаливое `SET NULL` | 10/10 без потери; второй запрос ждёт |
| Отправка годового плана vs утверждение плана | могла пропустить план | 409 + повторная отправка; частичного плана нет |

Исправления:

- `import_service`: `IntegrityError` при commit → 409 «Эту выгрузку уже сохраняет
  другой пользователь — повторите загрузку» (тест в `test_import_receipts.py`).
- `purchase_plan_service`: `SELECT … FOR UPDATE` строки плана в правке, отправке,
  утверждении, возврате, удалении — правки и согласование сериализуются.
- `batch_service` / `customs_service` / API позиций: та же блокировка партии при
  правке, импорте позиций, растаможке и удалении.
- `batch_service._lock_plan_item`: привязка поступления блокирует строку плана;
  удаление строки и привязка больше не проходят одновременно.

Остаточные риски: полная одновременная правка плана и поступления (разные строки,
не один ресурс) не воспроизводилась; внешняя блокировка дольше 30 с не проверялась.

## 4. Доступы — пройдено, один дефект UI исправлен

Матрица API (2027 читаем, 2028 черновик): все проверки совпали.

- План закупок: продажи и коммерция — 403; закупки, импорт, ГД — 200; править могут
  закупки и импорт; утверждает только ГД; удаляет только директор по закупкам.
- План продаж: менеджер видит только свой (чужой — 403); коммерция, закупки, ГД, импорт
  видят все.
- Годовой план: продажи, коммерция, закупки, ГД — 200; импорт — 403.
- Пользователи: только коммерция и ГД.
- Поступления: смотрят все; правят закупки и импорт; отменяет растаможку только
  директор по закупкам.
- Без сессии — 401; загрузки поступлений — только закупки.

В браузере:

- **Продажи:** нет «Плана закупок сырья»; поступление read-only («Закрыть», без
  «Сохранить/Удалить/Растаможить»).
- **Коммерция:** нет «Плана закупок сырья»; годовой план открывается; поступление
  read-only.
- **Менеджер по закупкам (импорт):** план 2029 редактируется («Сохранить»,
  «Отправить», «Добавить сырьё»); в поступлении — select «Строка плана» с привязкой;
  «Сохранить/Удалить» есть.
- **Исполнительный директор:** у плана на проверке — только «Утвердить»/«Вернуть»;
  утверждение кнопкой прошло (статус «Утверждён»); поступление read-only.
- **Директор по закупкам:** редактирует план и поступление (проверено ранее).

**Исправлено в интерфейсе:** карточка поступления была редактируемой для всех ролей —
продажи/коммерция/ГД видели поля и «Сохранить», а сервер отвечал 403. Теперь паспорт и
секции карточки обёрнуты в отключённые `fieldset` (тумблеры секций остаются рабочими):
поля не редактируются и читаются тёмным текстом, «Добавить»/«Убрать» скрыты, кнопок
«Сохранить», «Удалить», «Растаможить» нет, в футере — «Закрыть». Названия товаров в
режиме чтения — текстом; e2e поступлений переведены на роль директора по закупкам.

## 5. Читаемость, 20+ строк, тёмная тема

- 1280 px: план 2027 — 2 колонки месяцев в ряд, таблица влезает (956/956), правая
  колонка не обрезана; страница 1268 px на две строки. Карточка поступления — 5
  аккордеонов, открыты только позиции.
- 1440 px: таблица плана 1116 px, страница 1056 px; 1920 px: 1596 и 1080 px.
  Горизонтальной прокрутки нет, обрезок и наложений нет.
- **24 строки, 1280 px:** 288 карточек месяцев, строка ~317 px, вся страница ~8117 px
  (около 8 экранов). Таблица по ширине влезает, группировка по позициям не разъезжается,
  но работать с 24 строками тяжело: это главное UX-ограничение. Рекомендация — свернуть
  график месяца в компактную полосу/раскрытие по позиции, а не 12 карточек в каждой
  строке.
- По итогам vision-проверки 24 строк исправлено: «Убрать» была сжата в колонку 20 px и
  ломалась по буквам — теперь «×» 24×24 с отступом 8 px и aria-label/title; поля строки
  выровнены по центру; ширина колонки действий 4 %, графика — 25 % (пузырьки не
  обрезаются, 2×110 px). Полные имена сырья/поставщика — в title (нативные select не
  показывают многоточие). «Удалить» у плана в кадре импорта нет — это RBAC: кнопка
  только у директора по закупкам.
- Строка «факт 0 / 0 %» под количеством остаётся в две строки — так оформлен годовой
  факт; это не ошибка вёрстки.
- Тёмной темы нет: при системной тёмной теме приложение остаётся светлым
  (`color-scheme: light`), контраст не ломается; это не дефект, а отсутствующая функция.
- Замечания UX (не блокируют): длинное имя поставщика сокращается на 1280 (полное — в
  подсказке); в карточке поступления дублируются итоги и курс; шапка таблицы переносит
  «%» и «₽». Попутно убраны дублирующая строка месяцев и третий счётчик «разложено».

## 6. Нагрузка и блокировки

- 200 запросов × 3 endpoint (план 2027, поступления 2027, остатки), 40 потоков:
  p95 ≈ 0,9–1,2 с, максимум 1,6 с, **ни одного 5xx**.
- 10 одновременных сохранений плана из 24 строк: сериализуются блокировкой, максимум
  376 мс, 5xx нет, после — 24 строки.
- Внешняя блокировка строки плана на 5 с: сохранение подождало 4,36 с и вернуло 409
  (план утверждён), без таймаута и 500. Приложение ждёт блокировку, а не падает.
- Один процесс uvicorn; при 40 одновременных запросах растёт очередь (p95 ~1 с).
  Для пяти пользователей приемлемо; несколько воркеров не проверялись.

## 7. Что не проверено

- Полная одновременная правка плана и поступления (разные ресурсы).
- Смена привязки у растаможенной партии в UI (бэкенд-тест есть).
- Удаление связанной строки в UI (API даёт 409; как показывает себя кнопка — не смотрел).
- 24 строки на 1440/1920 (измерено на 1280), 12 месяцев с фактом в каждом месяце.
- Тёмная тема (её нет), клавиатурная навигация, hover/focus.
- Внешняя блокировка дольше 30 с, несколько воркеров uvicorn.
- Обрезка длинных имён в нативных select (многоточия нет; title есть).
- Alembic: схема создаётся `create_all`, колонка на стенде добавлена вручную.
