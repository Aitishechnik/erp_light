# Сценарий: сигнал закупкам при перевыполнении плана (2026-11-05)

Проверка цепочки на живом стенде «2027»: факт марта выше плана → закрытие месяца →
закупщик получает предложение увеличить план закупок. Всё выполнено через API стенда под
ролями `commercial`, `purchase`, `executive`; демо-данные стенда пересобраны скриптом.

## Модель

* План закупок — распределение: позиция продаж → сырьё + норма (кг на единицу).
* Факт 1С за месяц сравнивается с планом продаж того же месяца.
* Факт больше плана — сырья не хватило; добавка = превышение × норма, по каждой строке
  (основная и альтернативы). Это единственный случай, когда план закупок растёт.
* Недобор и его перенос на следующий период закупки не трогают: товар уже закуплен и учтён.
* Склад и остатки не участвуют.

## Что сделано

1. Стенд пересобран скриптом `scripts/stand_2027.py` (reset → clients → plans → files):
   три плана продаж, годовой план согласован, план закупок 14 + 6 строк.
2. В план закупок внесены нормы (20 строк, основные и альтернативы), план возвращён в
   работу, заполнен, снова отправлен и утверждён.
3. Сгенерирована выгрузка «Продажи за Март 2027» (158 строк): по арахису ×1,25,
   финикам ×1,15, кураге ×1,10 к плану, по остальным ×0,65. Загружена: 158 строк факта,
   несопоставленных нет.
4. Март закрыт с решением «Принять как есть». При закрытии отправлен сигнал закупщикам.

Сообщение «Продажи за март 2027 выше плана: позиций 3, строк плана закупок 5 — нужно
увеличить план закупок» со ссылкой на план и строками:

Итого 1 495,936 кг по пяти строкам (сумма по разным видам сырья — только для справки).

На плане закупок: плашка «Запрос на пересмотр отправлен исполнительному директору»,
нормы и потребность по строкам. Запас/дефицит равен нулю: план продаж не менялся, поэтому
потребность по норме осталась прежней — предложение живёт в сообщении, а количества
закупщик меняет после возврата плана в работу.

## Что проверено и чего нет

* Перенос недобора больше не сигналит: тест `test_correction_does_not_touch_purchase_plan`.
* Факт в пределах плана сигнала не даёт: `test_no_signal_when_fact_meets_plan`.
* Месяц с пустой выгрузкой закрывается: `test_empty_sales_report_closes_month`.
* Сообщение видят обе роли закупок (проверено API под `purchase` и `import`).
* Не проверено: фактический клик по ссылке из сообщения, 1024 px и мобильная, тёмная тема,
  клавиатура; авто-черновик правок не создаётся (так и задумано).
