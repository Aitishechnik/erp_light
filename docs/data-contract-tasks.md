# Контракт данных: таск-трекер «Задачи»

Статус: **версия 2 от 2026-11-01** (после первого запуска). Этап 1 реализован:
задачи, этапы, отчёты, файлы, Гант, служебные сообщения. Что изменилось во второй
версии — см. §12, что осталось на этап 2 — §11.

Таблицы: `tasks`, `task_steps`, `task_reports`, `task_report_files`; файлы лежат
в `data/attachments/<id задачи>/`.

## 1. Границы

Внутри: задачи **коммерческого отдела**, этапы с датами, приоритет, промежуточные
и финальный отчёт исполнителя, файлы к отчётам, экран «как в Ганте», служебные
сообщения участникам.

Вне: почтовые уведомления, напоминания по таймеру, зависимости между задачами,
перетаскивание дат мышью, шаблоны задач, привязка задачи к клиенту/партии/плану
(см. §11 — этап 2).

## 2. Роли и видимость

Трекер — **только коммерческий отдел**. Отдел закупок раздел не видит.

| Роль | Ставит задачи | Видит |
|---|---|---|
| Исполнительный директор | менеджерам, ассистенту, коммерческому директору | все задачи |
| Коммерческий директор | менеджерам, ассистенту | все задачи отдела |
| Менеджер по продажам | — | только свои (где исполнитель) |
| Ассистент отдела продаж | — | только свои (где исполнитель) |
| Директор по закупкам, менеджер по закупкам (импорт) | — | раздел недоступен |

| Действие | Кто |
|---|---|
| Поставить задачу | коммерческий или исполнительный директор |
| Изменить задачу и этапы | постановщик, исполнительный директор |
| Отложить, возобновить, отозвать | постановщик, исполнитель, исполнительный директор |
| Вернуть в работу после закрытия | постановщик, исполнительный директор |
| Прислать отчёт (промежуточный и финальный) | **только исполнитель** |
| Приложить файл к отчёту | исполнитель, постановщик |
| Удалить задачу | постановщик, исполнительный директор — пока нет отчётов |

**Задача принимается автоматически.** Исполнитель не подтверждает её: после
постановки задача сразу в статусе «В работе», а исполнителю приходит сообщение.

## 3. Приоритет

`green` — низкий (можно сдвинуть), `yellow` — обычный, `red` — высокий
(срывает сроки других). На экране: цвет полосы и цветной кружок у названия;
фильтры «красные», «просроченные», «мои».

## 4. Модель данных

### `tasks`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | ключ |
| `title` | varchar(255), not null | название |
| `description` | text, null | описание, что нужно сделать |
| `priority` | varchar(16), not null | `green`/`yellow`/`red` |
| `status` | varchar(16), not null | см. §5 |
| `progress` | int, not null, 0–100 | из последнего промежуточного отчёта |
| `start_date`, `due_date` | date, not null | сроки задачи; `due_date >= start_date` |
| `assignee_id` | uuid → users, not null | исполнитель |
| `created_by_id` | uuid → users, not null | постановщик |
| `closed_at` | timestamptz, null | когда закрыта финальным отчётом |
| `created_at`, `updated_at` | timestamptz | |

### `task_steps` — этапы внутри задачи (строки Ганта второго уровня)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | ключ |
| `task_id` | uuid → tasks, cascade delete | задача |
| `title` | varchar(255), not null | название этапа |
| `start_date`, `due_date` | date, not null | сроки этапа |
| `is_done` | bool, not null, default false | закрыт промежуточным отчётом |
| `position` | int, not null | порядок в списке |

Правила дат и порядка:

1. `due_date >= start_date` у задачи и у этапа; **этап укладывается в сроки задачи**
   (не раньше `start_date` задачи и не позже её `due_date`).
2. **Этапы не пересекаются и идут по порядку**: следующий начинается не раньше
   `due_date + 1` предыдущего. Если задача с 1 по 30, а первый этап 1–15, второй
   может начаться только 16-го и закончиться не позже 30-го.
3. Нарушение — 422 с текстом, где какой этап мешает: «Этап не может начаться
   раньше 16.11.2026: предыдущий этап «…» заканчивается 15.11.2026».

**Этап закрывается только промежуточным отчётом исполнителя** — по сроку или
раньше. Галочки «выполнен» нет: отчёт по этапу ставит `is_done = true`. Этап, чей
срок наступил, а отчёта нет, показывается как «нужен отчёт». Удалить этап, по
которому уже есть отчёт, нельзя (история).

### `task_reports` — отчёты исполнителя

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | ключ |
| `task_id` | uuid → tasks, cascade delete | задача |
| `step_id` | uuid → task_steps, set null | этап, который закрывает отчёт; пусто — отчёт по задаче |
| `author_id` | uuid → users | исполнитель |
| `kind` | varchar(16) | `interim` или `final` |
| `progress` | int, not null, 0–100 | только `interim`; у `final` = 100 |
| `text` | text, not null | что сделано / итог; не короче 3 символов |
| `created_at` | timestamptz | |

Отчёты не редактируются и не удаляются — это история. Промежуточный отчёт по
задаче меняет `tasks.progress` из формы; отчёт по этапу закрывает этап и считает
готовность задачи как **долю закрытых этапов** (1 из 2 — 50 %). Финальный отчёт пишет
`progress = 100`, ставит `status = done` и `closed_at`. Повторный финальный отчёт
после возврата в работу разрешён; действует последний.

### `task_report_files` — файлы к отчёту

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | ключ |
| `report_id` | uuid → task_reports, cascade delete | отчёт |
| `task_id` | uuid → tasks, cascade delete | для проверки прав и уборки |
| `original_name` | varchar(255) | имя как у пользователя |
| `stored_name` | varchar(80) | `<uuid><расширение>` на диске |
| `size_bytes` | int | размер |
| `content_type` | varchar(128) | |
| `uploaded_by_id` | uuid → users | |

## 5. Статусы

`new` (новая) — только у старых задач до версии 2; новые создаются сразу
`in_progress` (в работе). Дальше `done` (выполнена) — финальным отчётом.
`postponed` (отложена) и `cancelled` (отозвана) — боковые.
Закрытая задача правкам не подлежит, кроме возврата в работу.

Просрочка **не хранится**: если `due_date < сегодня` и статус не `done`/`cancelled`,
задача считается просроченной на экране и в фильтре.

## 6. Файлы

- Каталог `data/attachments/<task_id>/` (в git не попадает), права — только через API.
- До **10 МБ** на файл, до **10 файлов** на отчёт; типы: pdf, xlsx, xls, docx, doc,
  png, jpg, jpeg, zip. Иное — 415, больше размера — 413 с понятным текстом.
- Скачивание — с исходным именем; чужой файл отдаётся только участникам задачи (§2).
- Файлы крепятся к отчёту, а не к задаче: «что приложено к отчёту» видно в истории.

## 7. API

| Метод и путь | Что делает |
|---|---|
| `GET /tasks` | список с этапами и последним отчётом; фильтры `mine`, `status`, `priority`, `overdue`, `assignee_id`, `from`, `to` |
| `POST /tasks` | создать (только директора); задача сразу в работе |
| `GET /tasks/{id}` | карточка: задача, этапы, отчёты, файлы, доступные действия |
| `PATCH /tasks/{id}` | изменить (по §2) |
| `DELETE /tasks/{id}` | удалить, если отчётов нет |
| `POST /tasks/{id}/status` | в работу, отложить, возобновить, отозвать, вернуть |
| `POST /tasks/{id}/steps`, `PATCH/DELETE /tasks/{id}/steps/{step_id}` | этапы |
| `POST /tasks/{id}/reports` | отчёт: `kind`, `text`, `progress`, `step_id` |
| `POST /tasks/{id}/reports/{report_id}/files` | загрузка файла (multipart) |
| `GET /tasks/{id}/reports/{report_id}/files/{file_id}` | скачать |
| `DELETE /tasks/{id}/reports/{report_id}/files/{file_id}` | удалить файл |
| `GET /tasks/assignees` | кому можно ставить задачу (зависит от роли постановщика) |

## 8. Экран

- Меню: **«Задачи»** — один верхний пункт (группа из одного раздела убрана),
  виден только коммерческому отделу.
- Гант: слева название задачи, приоритет, исполнитель, срок; справа шкала недель
  с подписью месяца, линия «сегодня», горизонтальная прокрутка. Задача
  раскрывается в этапы. Полоса задачи залита по `progress` на цвет приоритета;
  просрочка — красная обводка и подпись «просрочено на N дн.».
- Кнопка «Сегодня» прокручивает шкалу к текущему дню.
- Карточка — `#/tasks/<id>`: описание, сроки, этапы, форма отчёта
  (этап, вид, %, текст, файлы), история отчётов с вложенными файлами.
- Кнопка «＋ Новая задача» — только у коммерческого и исполнительного директоров.
- Отчёт по этапу открывается кнопкой в строке этапа: этап подставляется в форму,
  вид отчёта фиксируется «промежуточный».

## 9. Служебные сообщения

События задач пишутся в `audit_events` (`entity_kind = 'task'`, ссылка
`#/tasks/<id>`) и адресуются конкретному сотруднику (метка `user:<uuid>` в
`audience` рядом с ролями):

| Событие | Кому |
|---|---|
| Задача поставлена | исполнителю |
| Задача изменена (сроки, приоритет, этапы, исполнитель) | исполнителю, прежнему исполнителю |
| Задача отложена / возобновлена / отозвана | исполнителю |
| Промежуточный отчёт (по задаче или этапу) | постановщику |
| Финальный отчёт, задача выполнена | постановщику и исполнительному директору |
| Задача возвращена в работу | исполнителю и исполнительному директору |
| Задача удалена | исполнителю и исполнительному директору |

Сообщения видны в колокольчике и в «Служебных сообщениях»; рабочие события
задачи остаются в журнале действий. Напоминаний по таймеру (просрочка) нет.

## 10. Тесты и приёмка

- pytest: роли и видимость (§2), авто-принятие, порядок и сроки этапов, закрытие
  этапа только отчётом, финальный отчёт закрывает задачу, лимиты файлов,
  сообщения исполнителю и постановщику.
- vitest: расчёт полос Ганта, права на кнопки, закрытие этапа отчётом.
- e2e: коммерческий ставит задачу → добавляет этап → менеджер закрывает этап
  отчётом → финальный отчёт с файлом → задача «Выполнена» → постановщик видит
  сообщение; проверка в браузере и консоль без ошибок.

## 11. Этап 2 (после приёмки версии 2)

Перетаскивание дат мышью, зависимости и вехи, шаблоны задач, привязка задачи к

## 12. Что изменилось во второй версии (решения)

1. Трекер — только коммерческий отдел; добавлена роль **ассистент отдела продаж**
   (`sales_assistant`, демо-логин `assistant`). Закупки раздел не видят.
2. Ставить задачи могут только коммерческий и исполнительный директора; ГД может
   ставить задачу и коммерческому директору.
3. Задача принимается автоматически: статус «В работе» с момента постановки.
4. Этапы идут строго по порядку и не пересекаются; этап закрывается только
   промежуточным отчётом, отчёт по этапу может прийти раньше срока.
5. Постановщик получает сообщения об отчётах, исполнитель — о постановке,
   изменении и отзыве задачи.
