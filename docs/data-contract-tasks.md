# Контракт данных: таск-трекер «Задачи»

Статус: **согласован 2026-11-01, этап 1 реализован** (задачи, этапы, отчёты,
файлы, Гант, журнал). Пункты §11 — следующий этап. Таблицы: `tasks`, `task_steps`,
`task_reports`, `task_report_files`; файлы лежат в `data/attachments/<id задачи>/`.

## 1. Границы

Внутри: задачи сотрудников, этапы (шаги) с датами, приоритет, промежуточные и
финальный отчёт менеджера, файлы к отчётам, экран «как в Ганте».

Вне: почтовые уведомления, напоминания по таймеру, зависимости между задачами,
перетаскивание дат мышью, шаблоны задач, привязка задачи к клиенту/партии/плану
(см. §11 — этап 2).

## 2. Роли и видимость

Задача видна **постановщику**, **исполнителю** и всем трём директорам
(коммерческий, по закупкам, исполнительный). Менеджеры (продаж, импорта) видят
только задачи, где они участник.

| Действие | Кто |
|---|---|
| Создать задачу | любой активный сотрудник; постановщик по умолчанию — автор |
| Изменить сроки, приоритет, исполнителя, описание | постановщик, директор |
| Взять в работу, отложить, отменить | исполнитель, постановщик |
| Добавить промежуточный отчёт | исполнитель |
| Добавить финальный отчёт (закрывает задачу) | исполнитель, постановщик |
| Вернуть в работу после финального отчёта | постановщик, директор |
| Удалить задачу | постановщик или директор, **только если отчётов нет** |
| Удалить файл отчёта | автор отчёта, директор, пока задача не закрыта |

## 3. Приоритет

`green` — низкий (можно сдвинуть), `yellow` — обычный, `red` — высокий
(срывает сроки других). На экране: цвет полосы и цветной кружок у названия;
фильтры «красные», «просроченные», «мои».

## 4. Модель данных

### `tasks`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | ключ |
| `title` | varchar(255), not null | название |
| `description` | text, null | описание, что нужно сделать |
| `priority` | varchar(16), not null | `green`/`yellow`/`red` |
| `status` | varchar(16), not null | см. §5 |
| `progress` | int, not null, 0–100 | берётся из последнего промежуточного отчёта |
| `start_date`, `due_date` | date, not null | плановые сроки; `due_date >= start_date` |
| `assignee_id` | uuid → users, not null | исполнитель |
| `created_by_id` | uuid → users, not null | постановщик |
| `closed_at` | timestamptz, null | когда закрыта финальным отчётом |
| `created_at`, `updated_at` | timestamptz | |

### `task_steps` — этапы внутри задачи (строки Гантта второго уровня)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | ключ |
| `task_id` | uuid → tasks, cascade delete | задача |
| `title` | varchar(255), not null | название этапа |
| `start_date`, `due_date` | date, not null | сроки этапа |
| `is_done` | bool, not null, default false | галочка «выполнен» |
| `position` | int, not null | порядок в списке |

Правило дат: `due_date >= start_date` у задачи и у этапа; **этап должен
укладываться в сроки задачи**. Иначе 422 с текстом «Этап выходит за сроки задачи:
расширьте сроки задачи или сузьте этап». Даты этапам не пересекаться не обязаны.

### `task_reports` — отчёты менеджера

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | ключ |
| `task_id` | uuid → tasks, cascade delete | задача |
| `author_id` | uuid → users | кто написал |
| `kind` | varchar(16) | `interim` или `final` |
| `progress` | int, not null, 0–100 | только для `interim`; у `final` = 100 |
| `text` | text, not null | что сделано / итог; не короче 3 символов |
| `created_at` | timestamptz | |

Отчёты не редактируются и не удаляются — это история. Промежуточный отчёт меняет
`tasks.progress` и переводит задачу в `in_progress`. Финальный отчёт пишет
`progress = 100`, ставит `status = done` и `closed_at`. Повторный финальный отчёт
после возврата в работу разрешён; действует последний.

### `task_report_files` — файлы к отчёту

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | ключ |
| `report_id` | uuid → task_reports, cascade delete | отчёт |
| `task_id` | uuid → tasks, cascade delete | для проверки прав и уборки |
| `original_name` | varchar(255) | имя как у пользователя |
| `stored_name` | varchar(80) | `<uuid><расширение>` на диске |
| `size_bytes` | int | размер |
| `content_type` | varchar(128) | |
| `uploaded_by_id` | uuid → users | |

## 5. Статусы

`new` (новая) → `in_progress` (в работе) → `done` (выполнена).
`postponed` (отложена) и `cancelled` (отменена) — боковые.
Отменённая и выполненная задача правкам не подлежит, кроме возврата в работу.

Просрочка **не хранится**: если `due_date < сегодня` и статус не `done`/`cancelled` —
задача считается просроченной на экране и в фильтре.

## 6. Файлы

- Каталог `data/attachments/<task_id>/` (в git не попадает), права — только через API.
- До **10 МБ** на файл, до **10 файлов** на отчёт; типы: pdf, xlsx, xls, docx, doc,
  png, jpg, jpeg, zip. Иное — 415, больше размера — 413 с понятным текстом.
- Скачивание — с исходным именем; чужой файл отдаётся только участникам задачи (§2).
- Файлы крепятся к отчёту, а не к задаче: «что приложено к отчёту» видно в истории.

## 7. API

| Метод и путь | Что делает |
|---|---|
| `GET /tasks` | список с этапами и последним отчётом; фильтры `mine`, `status`, `priority`, `overdue`, `assignee_id`, `from`, `to` |
| `POST /tasks` | создать |
| `GET /tasks/{id}` | карточка: задача, этапы, отчёты, файлы, доступные действия |
| `PATCH /tasks/{id}` | изменить (по §2) |
| `DELETE /tasks/{id}` | удалить, если отчётов нет |
| `POST /tasks/{id}/status` | смена статуса (в работу, отложить, отменить, вернуть) |
| `POST /tasks/{id}/steps`, `PATCH/DELETE /tasks/{id}/steps/{step_id}` | этапы |
| `POST /tasks/{id}/reports` | отчёт (JSON: `kind`, `text`, `progress`) |
| `POST /tasks/{id}/reports/{report_id}/files` | загрузка файла (multipart) |
| `GET /tasks/{id}/reports/{report_id}/files/{file_id}` | скачать |
| `DELETE /tasks/{id}/reports/{report_id}/files/{file_id}` | удалить файл |

## 8. Экран

- Меню: **«Задачи»** — один верхний пункт (группа из одного раздела убирается),
  открывает трекер сразу, без раскрытия.
- Гантт: слева название задачи, приоритет, исполнитель, срок; справа шкала недель
  с подписью месяца, линия «сегодня», горизонтальная прокрутка. Задача
  раскрывается в этапы. Полоса задачи залита по `progress` на цвет приоритета;
  просрочка — красная обводка и подпись «просрочено на N дн.».
- Кнопка «Сегодня» прокручивает шкалу к текущему дню. Окно строится по срокам
  задач с запасом в неделю и выравнивается по понедельникам; фильтры сверху
  сужают список.
- Карточка — `#/tasks/<id>`: описание, сроки, этапы, форма отчёта
  (вид, %, текст, файлы), история отчётов с вложенными файлами.
- Пустой экран: «Задач пока нет — поставьте первую».

## 9. Журнал и колокольчик

Пишем в `audit_events` (существующая таблица, `entity_kind = 'task'`), ссылки вида
`#/tasks/<id>`: создана, изменена, смена статуса, отчёт добавлен, задача закрыта
финальным отчётом, удалена. Критические (задача закрыта, возвращена в работу) —
в колокольчик исполнительному директору, как сейчас устроено; остальные роли
подключаются вместе с версией 2 уведомлений. Напоминаний по таймеру в этапе 1 нет.

## 10. Тесты и приёмка

- pytest: права по §2, переходы §5, даты этапов, финальный отчёт закрывает
  задачу, лимиты файлов, скачивание чужим пользователем — 403.
- vitest: расчёт полос Гантта (границы, просрочка, проценты), фильтры.
- e2e: создать задачу → добавить этап → промежуточный отчёт с файлом →
  финальный отчёт → задача `done`; проверка в браузере (§8) и консоль без ошибок.

## 11. Этап 2 (после приёмки этапа 1)

Перетаскивание дат мышью, зависимости и вехи, шаблоны задач, привязка задачи к
объекту ERP (клиент, поступление, план) и переход по ссылке из задачи,
напоминания о просрочке, выгрузка списка в xlsx.

## 12. Открытые вопросы (решения по умолчанию, поправьте)

1. Ставить задачу может **любой сотрудник на любого** — так проще всего и не
   требует согласования; ограничение «только директора» добавляется правом.
2. Финальный отчёт **закрывает задачу сразу**, без отдельного согласования;
   постановщик может вернуть в работу.
3. Этапы необязательны: задача без этапов рисуется одной полосой.
