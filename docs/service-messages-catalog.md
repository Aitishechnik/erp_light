# Служебные сообщения: типы по ролям

Версия 2 (2026-11-01). Критические события по-прежнему видит **исполнительный
директор**, а события задач адресуются **конкретному сотруднику** — исполнителю
или постановщику (см. таблицу ниже). Остальные роли подключаются следующими
версиями; их список лежит в
[`data-contract-notifications.md`](data-contract-notifications.md) (§4–5).

## Что уже приходит (версия 1)

| Событие | Когда пишется | Кто видит |
|---|---|---|
| План продаж утверждён | КД утверждает план менеджера | ГД |
| Изменены строки плана продаж | План сохранён (в т.ч. при утверждённом плане) | ГД |
| План продаж удалён | Удалён черновик плана | ГД |
| Корректировка плана утверждена | КД или ГД утвердили корректировку | ГД |
| Годовой план отдела согласован | ГД согласовал годовой план | ГД |
| Согласование годового плана снято | Изменился план менеджера | ГД |
| Месяц закрыт / открыт заново | Итоги месяца | ГД |
| Принято решение месяца | Перенос объёма / принять как есть | ГД |
| Созданы черновики корректировок | Кнопка переноса у закрытого месяца | ГД |
| Изменены строки плана закупок | Закупщик сохранил план | ГД |
| План закупок утверждён / возвращён в работу | ГД или закупщик | ГД |
| Изменены позиции поступления | Правка карточки партии | ГД |
| Растаможка поступления | Растаможка или её отмена | ГД |
| Поступление удалено | Удаление карточки | ГД |
| Заведена / изменена номенклатура | Справочник номенклатуры | ГД |
| Заведён / изменён контрагент | Справочник контрагентов (в т.ч. менеджер клиента) | ГД |
| Изменена страна и срок доставки | Справочник стран, показываем «было → стало» | ГД |
| Неудачная попытка входа | Неверный пароль или неизвестный логин | ГД |
| Задача поставлена | Постановщик назначил исполнителя | Исполнитель |
| Задача изменена | Сроки, приоритет, этапы или исполнитель | Исполнитель (и прежний) |
| Задача отозвана / отложена / возобновлена | Смена статуса | Исполнитель |
| Отчёт по этапу или задаче | Исполнитель прислал промежуточный отчёт | Постановщик |
| Задача выполнена | Исполнитель закрыл задачу финальным отчётом | Постановщик, ГД |
| Задача возвращена в работу | Постановщик вернул закрытую задачу | Исполнитель, ГД |
| Задача удалена | Постановщик удалил задачу без отчётов | Исполнитель, ГД |

Служебное сообщение может быть адресовано не только роли, но и конкретному
сотруднику (`audience` = `user:<uuid>`). Так задачи находят своего исполнителя и
постановщика: колокольчик и «Служебные сообщения» показывают их только адресату.

В журнале действий видно всё то же самое плюс подпись «критическое/рабочее»,
фильтр по тексту и кнопку «Отметить всё прочитанным». Журнал исполнительному
директору показывает действия **всех** сотрудников, остальным — только свои.

## Что планируется добавить по ролям (версия 3)

| Роль | События |
|---|---|
| Исполнительный директор | всё, что уже есть + рабочие шаги (отправка на проверку, загрузки) |
| Коммерческий директор | утверждение и отклонение планов менеджеров, корректировки, годовой план, закрытие месяца, причины отклонений, смена менеджера клиента |
| Директор по закупкам | план закупок (сохранение, утверждение, пересмотр), приёмка и растаможка поступлений, страны, номенклатура сырья |
| Менеджер по закупкам (импорт) | поступления и партии: создание из 1С, правка позиций, растаможка; загрузки справочников |
| Менеджер по продажам | свои планы (утверждён/отклонён), свои корректировки, строки итогов по своим клиентам, закрепление клиента |

Правила:
1. Критические события остаются у ГД всегда; остальным — по матрице.
2. «Свои» определяется по клиенту/плану, а не по роли: чужое менеджер не видит.
3. Рабочие (info) события в колокольчик не идут, но пишутся в журнал.

## Ссылки на объект

Каждая строка журнала и панели, у которой есть объект, — ссылка. Она открывает
нужное место, а не просто раздел: адрес вида `#/month/2027/1`, `#/receipt/<id>`,
`#/countries/<id>`. Ссылку можно скопировать и переслать — коллега попадёт сразу
к объекту, если у него есть права на раздел.

| Что за событие | Куда ведёт ссылка |
|---|---|
| План продаж (утверждён, изменён, удалён, корректировка) | `#/sales-plan/<год>/<id плана>` |
| Годовой план отдела | `#/annual-plan/<год>` |
| Итоги месяца (закрыт, решение, перенос, причины) | `#/month/<год>/<месяц>` |
| План закупок | `#/purchase-plan/<год>` |
| Поступление | `#/receipt/<id>` — сразу карточка |
| Номенклатура | `#/nomenclature/<id>` — строка подсвечена |
| Контрагент | `#/counterparties/<id>` — строка подсвечена |
| Страна | `#/countries/<id>` — строка подсвечена |
| Вход, очистка журнала | без объекта (очистка ведёт в журнал) |

## Очистка журнала (ответ на открытый вопрос)

С 1 марта исполнительному директору каждый месяц приходит предложение
«Журнал за прошлый год: записей N. Можно очистить». Очистка удаляет записи
за 1 января — 31 декабря прошлого года и только после подтверждения;
в журнале остаётся запись «Журнал за 2025 год очищен: удалено записей N».
До марта предложения нет: прошлый год считается «свежим».

Экспорт журнала — не делаем (решение продакт-менеджера). Уведомления —
только визуальные: колокольчик и журнал, почты и пушей нет.
