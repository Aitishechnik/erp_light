# «Итоги месяца»: как это работает

Разбор от 2026-11-04 по коду и [контракту](data-contract-monthly-results.md). Описывает
**текущее** поведение, включая места, где реализация отличается от контракта. Список
расхождений и задач — [backlog-month-results-2026-11-04.md](backlog-month-results-2026-11-04.md).

## 1. Что сравниваем

Отчёт отвечает на вопрос «кто и где не добрал объём в этом месяце». Сравниваются **план
продаж** и **факт продаж** по ключу **клиент × товар × месяц**.

| Показатель | Как получается |
|---|---|
| План, ед. | сумма количества по строкам утверждённых планов менеджеров за месяц |
| Факт, ед. | количество из выгрузки 1С; возвраты — минусом |
| Отклонение, ед. | факт − план |
| Исполнение, % | факт ÷ план × 100; пусто, если плана нет |
| Сумма, ₽ | сумма продажи из файла, справочно |

Строка попадает в одну из трёх групп: **по плану** (есть и план, и факт), **вне плана**
(продали то, чего не планировали), **не продано** (план есть, продаж ноль).

**Менеджер строки.** Берётся из плана, если эта пара клиент × товар есть ровно в одном
утверждённом плане на этот год; иначе — поле «Менеджер» в карточке клиента. Значок **«≠»**
у имени означает: клиент закреплён за другим менеджером, чем его план.

План в рублях не считается: в плане продаж цен нет (решение 07.10.2026). Штуки и килограммы
не складываются, поэтому в сводке считаются **строки**, а не «всего единиц».

## 2. Цепочка: кто и что должен сделать

Пункты 2.1–2.3 — предпосылки: без них отчёт будет пустым.

### 2.1. Справочники

`Администрирование → Загрузка данных` → карточки **«Номенклатура»** и **«Покупатели»**,
файлы `.xlsx` из 1С. Кто: менеджер по продажам, коммерческий директор, директор по закупкам,
исполнительный директор.

Из номенклатуры берутся карточки товаров, из покупателей — клиенты. Если в файле продаж
встретится клиент, которого нет в справочнике, **файл не примется целиком** — сначала
загружаем «Покупателей».

### 2.2. Менеджер у клиента

`Справочники → Контрагенты` → колонка **«Менеджер»** (в карточке клиента). Кто: те же роли
(справочник правят менеджер продаж, коммерческий директор, директор по закупкам,
исполнительный директор).

Если поле пустое, ответственный берётся из единственного утверждённого плана, где есть эта
пара клиент × товар. Если и там неоднозначно, строка попадает в «Менеджер не определён»: её
видит коммерческий директор, а менеджер — нет.

### 2.3. Годовой план продаж

Менеджер заполняет план на год (клиент × товар × месяц) и отправляет на проверку;
**коммерческий директор утверждает** каждый план (исполнительный директор может как
администратор). Итоговую подпись годового плана отдела ставит исполнительный директор, но
**отчёт смотрит только на утверждённые планы менеджеров**: неутверждённый план в расчёт не
идёт, и его продажи покажутся «вне плана».

Утверждённые корректировки плана уже применены к строкам к моменту расчёта.

### 2.4. Факт: файл 1С и загрузка

1С → отчёт **«Продажи»** за месяц → `.xlsx`. Файл грузится **как есть**, его не переделывают
в плоскую таблицу: приложение отличает клиента по жирной строке, позиции — по отступу.

`Загрузка данных → «Продажи за месяц»` → выбрать файл → **«Загрузить»**. Кто: коммерческий
директор и исполнительный директор (администратор).

Правила:

* период берётся из шапки файла («Период: Октябрь 2026 г.»); не распознан — файл не
  примется. Уточнить период в интерфейсе **нельзя**, только через API;
* повторная загрузка **заменяет месяц целиком** — дублей не будет, но и старые строки
  месяца исчезнут;
* одна строка на клиент × товар; повторы внутри файла складываются;
* возвраты — строки с минусом, так и сохраняются; месяц может уйти в минус;
* файл до 10 МБ; если больше — выгрузку делят;
* закрытый месяц файл не примет (409) — сначала «Открыть заново»;
* незнакомый клиент — отказ файла целиком, с именами клиентов.

### 2.5. Очередь сопоставления

Если позиция из файла не нашлась в номенклатуре или подходит несколько карточек, строка
**не идёт в итоги** и попадает в очередь на экране «Итоги месяца». Пока очередь не пуста,
**месяц нельзя закрыть** (загрузить новый файл — можно).

Кто сопоставляет: коммерческий и исполнительный директор. В очереди: поиск по названию →
выбор позиции → **«Сопоставить»**. Выбор запоминается и применяется в следующих месяцах.

### 2.6. Причины отклонений

Строка с отклонением (факт ≠ план) → **«+ причина»** → причина из списка (8 вариантов) →
комментарий (обязателен для «Другое», до 500 символов) → **«Сохранить»**.

Кто: менеджер — по своим строкам, коммерческий и исполнительный — по всем. Причина **не
меняет** план и факт: это объяснение, которое попадает в снимок месяца. Одна причина на
клиент × товар × месяц; автор виден в подсказке к плашке (дата в интерфейсе не показывается).
После закрытия причина не меняется.

### 2.7. Решение месяца

Пока месяц открыт: «Перенести в план продаж» / «Перенести в план закупок» (с месяцем
переноса) / «Принять как есть» → **«Сохранить решение»**. Кто: коммерческий и
исполнительный директор.

Решение можно не принимать — закрытию это не мешает; после закрытия оно не меняется.
Система планы не правит: «перенести» — это намерение, объём переезжает штатной
корректировкой.

### 2.8. Закрытие месяца

**«Закрыть месяц»** → панель подтверждения (строк, без причины, очередь) → **«Закрыть
месяц»**. Проверки: за месяц есть факт; очередь сопоставления пуста. Отсутствие причин
**не блокирует** — только показывается счётчиком.

Что происходит: пишется снимок (план, факт, отклонения, причины, решение, автор, дата) и
запись в журнал. Дальше месяц read-only: загрузка факта, причины и решение возвращают 409.

**«Открыть заново»** — коммерческий или исполнительный, причина обязательна, она видна в
шапке; прошлый снимок остаётся в истории.

### 2.9. Корректировки после решения «перенести в план продаж»

После закрытия и с решением «Перенести в план продаж» появляется **«Создать корректировки»**:
недобор (план − факт по каждой строке) раскладывается в **черновики** корректировок планов
менеджеров на месяц переноса. Утверждать — в «Планировании продаж» (коммерческий или
исполнительный директор).

Менеджер попадает в «пропущено» с причиной, если: клиент без менеджера; на год переноса нет
утверждённого плана; месяц переноса заморожен (прошедшие месяцы); у менеджера уже есть
открытая корректировка.

## 3. Экран «Итоги месяца»: что означает каждая кнопка

| Элемент | Что делает | Кому доступно |
|---|---|---|
| **Год**, **Месяц** | переключают период отчёта, ничего не сохраняют | всем, у кого есть отчёт |
| **Менеджер** | фильтр по ответственному; список строится из видимых строк | всем |
| **«только отклонения»** | оставляет строки, где факт ≠ план | всем |
| **«без причины»** | оставляет строки с отклонением и без причины | всем |
| **Поиск** | по клиенту, позиции и менеджеру | всем |
| плашка **«месяц открыт / закрыт»** | статус и, для закрытого, кто и когда закрыл, причина переоткрытия | всем |
| **«Закрыть месяц»** | панель подтверждения → снимок и запрет правок | коммерческий, исполнительный |
| **«Открыть заново»** | форма с обязательной причиной → месяц снова открыт | коммерческий, исполнительный |
| **«Решение месяца»** | выбрать вариант, месяц переноса (1–6 вперёд), комментарий → сохранить | коммерческий, исполнительный |
| **«Создать корректировки»** | черновики корректировок по недобору закрытого месяца | коммерческий, исполнительный |
| очередь: **поиск / позиция / «Сопоставить»** | связать строку файла с карточкой номенклатуры | коммерческий, исполнительный |
| **«+ причина»** / плашка причины | редактор причины в строке; внутри «Сохранить», «Убрать», «Отмена» | менеджер — своим, коммерческий и исполнительный — всем |
| сводная строка | строк, с отклонением, вне плана, не продано, без причины, факт ₽ | всем |

Дополнительно на экране: предупреждение «на год нет утверждённого плана — все продажи
считаются вне плана», пустой экран «за этот месяц продаж и плана нет» и подсказка, где
загрузить файл.

## 4. Роли

| Роль | Видит | Причина | Загрузка продаж | Сопоставление | Закрытие, решение |
|---|---|---|---|---|---|
| Менеджер по продажам | только свои строки | своим клиентам | нет | нет | нет |
| Ассистент отдела продаж | **отчёта нет** (нет пункта меню, API — 403) | — | нет | нет | нет |
| Коммерческий директор | всех | всем | да | да | да |
| Исполнительный директор | всех | всем (права администратора) | да | да | да |
| Директор по закупкам | всех, только чтение | нет | нет | нет | нет |
| Менеджер по закупкам (импорт) | **отчёта нет** (403) | — | нет | нет | нет |

Директор по закупкам видит отчёт, потому что от решения о переносе зависит план закупок,
но менять ничего не может. По контракту (§8) исполнительный директор причин не ставит, но
с 03.11.2026 у него права администратора — ставит.

## 5. Что важно знать про текущую версию

* Отчёт **считается на лету** из планов и факта. Снимок пишется в базу, но на экране не
  показывается, и истории версий в интерфейсе нет.
* На экране отчёта **нет кнопки загрузки** — только через «Загрузку данных».
* Очередь сопоставления **видна всем**, включая менеджеров, и не фильтруется по клиентам.
* На закрытом месяце редактор причины открывается, но сохранение вернёт ошибку 409.
* Месяц переноса в интерфейсе — только 1–6 месяцев вперёд.
* Сводка по менеджерам — строки / вне плана / не продано, без плана, факта и процента.
* Печати и выгрузки отчёта нет.
* План в рублях невозможен, маржа и PnL по клиентам сюда не входят.
