# Стенд «2027»: как повторить сценарий

Сценарий, приближенный к реальности: чистые планирование и поставки, живые
справочники и роли, моковые выгрузки «как из 1С» и полный месячный цикл.
Всё делается одним скриптом и проверяется в интерфейсе.

## Что получается в базе

| Что | Сколько |
|---|---|
| Номенклатура (готовая продукция, материалы, сырьё) | 1280 (не трогаем) |
| Контрагенты (клиенты, поставщики) | 1480 (не трогаем) |
| Клиенты на стенде | 15, по 5 на трёх менеджеров |
| Позиции плана продаж | 8 готовых позиций ↔ 8 видов сырья |
| План продаж 2027 | 1080 строк (3 плана × 360) |
| План закупок 2027 | 8 строк, 93,2 млн ₽ |
| Поступления | 24 партии, 22 с ценами и привязкой к плану |
| Продажи январь 2027 | 84 строки факта, 2 строки в очереди сопоставления |
| Продажи февраль 2027 | 94 строки факта |

Скрипт: [`scripts/stand_2027.py`](../scripts/stand_2027.py).

```sh
cd /mnt/extraspace/erp_lite
# сначала бэкап — см. «Бэкап перед очисткой»
backend/.venv/bin/python scripts/stand_2027.py reset     # очистка
backend/.venv/bin/python scripts/stand_2027.py clients   # 15 клиентов за менеджерами
backend/.venv/bin/python scripts/stand_2027.py plans     # план продаж → утверждение → план закупок
backend/.venv/bin/python scripts/stand_2027.py files     # выгрузки в data/mock/2027
backend/.venv/bin/python scripts/stand_2027.py receipts  # поступления файлом + цены и привязка
backend/.venv/bin/python scripts/stand_2027.py reasons   # причины недоборов января
```

`all` выполняет первые пять шагов подряд. Команда `reset` удаляет только
планирование, поставки, факты, итоги месяца, причины и журнал загрузок;
номенклатура, контрагенты, страны, курсы и пользователи остаются.

## Моковые выгрузки

`data/mock/2027` (в git не попадает):

* `Продажи за Январь 2027.xlsx`, `Продажи за Февраль 2027.xlsx` — отчёт «Продажи»
  1С: период в шапке («Период: Январь 2027 г.»), клиенты группами (жирным),
  позиции с отступом, итог в конце. Внутри заложены отклонения: недобор разной
  глубины, полное отсутствие продаж, продажи вне плана, возвраты минусом и две
  строки с названиями, которых нет в справочнике.
* `Импортные поступления 2027.xlsx` — 24 партии: те же 20 колонок, что у 1С.
* `Партия ИТ-2027-0001.xlsx`, `Партия ИТ-2027-0002.xlsx` — проверка загрузки позиций
  в карточке поступления (строки приходят без цены и без привязки к плану).

Поставки подогнаны под план января–марта: кешью закрыт на 55 %, миндаль приходит
только в феврале — это объясняет недобор и перенос объёма.

## Прогон цикла в интерфейсе

1. **Январь 2027** (`Отчёты → Итоги месяца`): загрузить «Продажи за Январь 2027»
   в `Администрирование → Загрузка данных`; сопоставить 2 строки в очереди;
   поставить причины недоборам; `Закрыть месяц`.
2. **Решение**: «Перенести в план продаж → Февраль 2027» и комментарий — **до**
   закрытия, иначе месяц закрыт без решения и его нужно переоткрывать.
3. **Черновики**: у закрытого месяца с решением «в план продаж» — кнопка
   `Создать корректировки`; утвердить их в `Планирование → Планирование продаж`
   (коммерческий **или** исполнительный директор). Февральский план вырастет.
4. **Февраль 2027**: загрузить продажи, поставить причины, решение
   «Перенести в план закупок → Март 2027», закрыть. Кнопки черновиков здесь нет:
   перенос закупки оформляется пересмотром плана закупок.
5. **План закупок сырья**: после переноса он показывает «План продаж пересмотрен»;
   директор по закупкам запрашивает пересмотр, ГД возвращает план в работу,
   закупщик правит количества, принимает изменения к сведению, отправляет, ГД
   утверждает.

## Что проверить по пути

* импорт в закрытый месяц — отказ 409 «Месяц закрыт…»;
* причина в закрытом месяце — отказ 409;
* чужой клиент для менеджера — строка недоступна (404, а не 403: сервер не
  раскрывает чужие строки);
* кнопка черновиков для решения «в план закупок» — отсутствует, API отвечает 400
  с объяснением;
* покрытие поступлениями в плане закупок: «факт …» и доля, % под количеством.
