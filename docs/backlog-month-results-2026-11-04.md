Составлено 2026-11-04 по итогам разбора [how-month-results-works.md](how-month-results-works.md).
**Статус на 2026-11-05: MR-1 … MR-4 реализованы, проверены гейтами и аудитом UI** (раздел
«Аудит 2026-11-05» в конце). Ниже — исходная постановка и что получилось на самом деле.

Что уже соответствует контракту: три группы строк, причины отклонений с автором, закрытие со

## MR-1. Кнопка «Загрузить продажи» на экране отчёта и уточнение периода (высокий)

**Что не так.** Контракт §9 обещает на экране отчёта кнопку «Загрузить продажи», но её нет:
файл грузится только через «Администрирование → Загрузка данных». Период берётся из шапки
файла, а уточнить его в интерфейсе нельзя — только параметрами API. Если 1С поменяет шапку,
пользователь видит ошибку и не может ничего сделать.

**Что сделать.** В шапке отчёта рядом с «Закрыть месяц» — кнопка «Загрузить продажи» для
коммерческого и исполнительного директора. Открывает небольшую панель: файл, необязательные
год и месяц (переопределяют шапку), кнопка «Загрузить». После успеха — перезагрузка отчёта и
сообщение «строк: N, в очереди: M, месяц заменён целиком». На закрытом месяце кнопки нет, вместо
неё — пояснение «месяц закрыт, откройте заново».

**Критерии готовности.**

* менеджер по продажам и директор по закупкам кнопки не видят;
* на закрытом месяце — пояснение, а не ошибка 409;
* повторная загрузка того же файла даёт те же цифры, очередь пересобирается;
* e2e: загрузили файл с экрана отчёта → обновились строки и очередь.

**Где.** `frontend/src/MonthResultsPage.tsx`, `frontend/src/api.ts` (передать `year`/`month`
в `uploadImport`), `backend/app/api/v1/imports.py` уже принимает параметры.

**Сделано.** Кнопка в шапке отчёта, панель с файлом и полями «Год»/«Месяц» (оба пустые — период
из шапки; заполнен только один — отказ с подсказкой). После успеха — сообщение и перезагрузка
отчёта. На закрытом месяце кнопки нет, вместо неё пояснение. Backend не менялся.

## MR-2. История снимков месяца (средний)

**Что не так.** Снимок пишется в `month_results.snapshot` и `month_result_snapshots`, но
эндпоинта `GET .../history` из контракта §11 нет и на экране истории нет. После «Открыть
заново» и повторной загрузки экран показывает новые цифры, а прежний снимок виден только в
базе. Проверить, что было зафиксировано при закрытии, пользователь не может.

**Что сделать.** `GET /api/v1/month-results/{year}/{month}/history` — список версий: номер,
когда и кто закрыл, итоги, решение. На экране — раскрывающаяся панель «История закрытий».
Снимки только для чтения, без кнопок правки.

**Критерии готовности.**

* после «закрыть → открыть → закрыть» в истории две версии с разными итогами;
* менеджер по продажам историю не видит (в снимке строки всех клиентов — это чужие данные);
* коммерческий, исполнительный и директор по закупкам видят историю;
* контракт §11 обновлён.

**Где.** `backend/app/api/v1/month_results.py`, `backend/app/services/month_close_service.py`,
`frontend/src/MonthResultsPage.tsx`.

**Сделано.** `GET /month-results/{year}/{month}/history` (коммерческий, исполнительный,
директор по закупкам) и панель «История закрытий»: версия, дата, кто закрыл, итоги, решение.
В снимок решения добавлены автор и дата (старые версии читаются с `null`). У менеджера по
продажам истории нет: в снимке строки всех клиентов.

## MR-3. Сводка по менеджерам по контракту (средний)

**Что не так.** Сейчас таблица «Менеджер / Строк / Вне плана / Не продано» и показывается
только если менеджеров больше одного. В контракте §9 — план, факт, отклонение, исполнение %,
строк с отклонением, раскрытие до клиентов и позиций. Фильтра по группе («по плану / вне
плана / не продано») тоже нет — только «только отклонения».

**Что сделать.** В сводке по менеджеру: строк, с отклонением, вне плана, не продано, без
причины, факт ₽. Раскрытие «менеджер → клиент → позиции». Отдельный фильтр по группе,
комбинируется с остальными. Количество разных товаров не суммировать — только строки и
рубли (правило контракта §2).

**Критерии готовности.**

* числа в сводке сходятся с детальной таблицей на данных октябрьского файла
  (33 клиента, 257 строк);
* раскрытие работает без заметных задержек;
* фильтр группы комбинируется с менеджером, поиском и «без причины».

**Где.** `frontend/src/MonthResultsPage.tsx` (+ unit-тесты на группировку).

**Сделано.** Сводка «менеджер → клиент → позиции» с колонками: строк, с отклонением, вне плана,
не продано, без причины, факт ₽. Раскрытие клиента показывает позиции с планом, фактом,
отклонением, исполнением и группой. Добавлен фильтр «Группа». Сводка показывается и при одном
менеджере (у менеджера — его клиенты). План/факт в единицах по менеджеру не суммируются:
разные товары в разных единицах, поэтому в сводке строки и рубли.

## MR-4. Очередь сопоставления не фильтруется по правам (высокий, найдено попутно)

**Что не так.** `month_unmatched` отдаёт все несопоставленные строки месяца любому, у кого
есть доступ к отчёту. Менеджер по продажам видит в очереди название позиции, клиента,
количество и сумму по **чужим** клиентам — это нарушает правило «менеджер видит только свои
клиенты».

**Что сделать.** Проще и по бизнес-модели правильнее: очередь — рабочий инструмент
коммерческого директора, поэтому отдавать её только тем, кто может сопоставлять
(коммерческий, исполнительный). Менеджеру и директору по закупкам — не отдавать; счётчик
«в очереди: N» им тоже не показывать.

**Критерии готовности.**

* менеджер не получает чужих строк очереди ни в API, ни на экране;
* закрытие месяца по-прежнему блокируется непустой очередью;
* тест на права: менеджер — очередь пуста, коммерческий — видит все строки.

**Где.** `backend/app/services/month_result_service.py`,
`backend/app/api/v1/month_results.py`, `frontend/src/MonthResultsPage.tsx`.

**Сделано.** Очередь отдаётся только коммерческому и исполнительному директору
(`MATCH_ROLES` в сервисе, права API — оттуда же). Менеджер и директор по закупкам получают
пустой список; экран им очередь не рисует. Закрытие по-прежнему блокируется непустой очередью —
её видит и проверяет тот, кто закрывает. Тест: менеджер — пусто, коммерческий — видит строки,
закрытие с очередью — 409.

## Аудит 2026-11-05

Живой стек: API `127.0.0.1:4111`, UI `127.0.0.1:4110`, БД проекта `5547`. Стенд «2027»:
январь — 165 строк, месяц закрыт (снимок от 01.11.2026, решение «Принять как есть»),
февраль — 158 строк плана без факта, месяц открыт. Проверено под коммерческим директором
(`commercial`) и менеджером по продажам (`sales`).

**Что проверено в браузере.**

* Январь: сводка по трём менеджерам (59 + 53 + 53 = 165 строк), раскрытие менеджера → клиента
  → позиций (Дикси: 11 строк, 10 отклонений, 1 вне плана; внутри — 184 кг «Чернослив»),
  панель «История закрытий» с версией 1 и суммой 15 241 181,59 ₽, решение в истории.
* Февраль: кнопка «Загрузить продажи», панель с файлом и полями «Год»/«Месяц», «Загрузить»
  неактивна без файла, «Отмена» закрывает панель; подтверждение закрытия показывает
  «Строк: 158, без причины: 158».
* Фильтр «Группа» = «вне плана» на январе: 7 строк, все с плашкой «вне плана» — совпадает
  со счётчиком сводки.
* Менеджер по продажам: 52 строки только его клиентов, один менеджер в сводке, кнопок
  «Загрузить продажи», «История закрытий», «Закрыть месяц» нет, очередь не показана,
  у каждой строки «+ причина».
* Консоль: JS-ошибок нет. 3 записи об ошибках — ожидаемые HTTP: два `401 /auth/me` до входа и
  `409` при попытке закрыть февраль без факта. Запросы экрана — 200.

**Исправлено по ходу аудита.**

* Закрытый месяц: плашки причин были кликабельны, редактор открывался, сохранение давало 409.
  Теперь плашки заблокированы, редактор не открывается, а открытый редактор закрывается при
  переходе месяца в «закрыт».
* Неудачное закрытие оставляло панель подтверждения открытой поверх сообщения об ошибке.
  Теперь панель закрывается, причина отказа видна сообщением.
* Пустой месяц подсказывал только «Загрузку данных» — теперь, если кнопка доступна, подсказка
  ведёт к «Загрузить продажи».
* Кнопки раскрытия сводки получили `aria-label` («Раскрыть менеджера: …», «Раскрыть клиента: …»).

**Не проверено.** Мобильная и 1024 px, клавиатурная навигация и скринридер, тёмная тема,
печать, реальная загрузка файла на стенд (чтобы не менять демо-данные февраля), поведение при
двух одновременных закрытиях.
